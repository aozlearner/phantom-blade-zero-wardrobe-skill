# 备份、验证与交付

## 离线检查先完成

先把同批角色和修复一起准备好，再运行游戏。确认 JS 语法、ABP/模型依赖、必要骨骼、材质槽、表行/NameMap 保留、新旧 ID 不冲突、注册名单、PNG 映射和语音选择。根据变更运行行为测试，不把固定旧数量或仅匹配实现文字的测试当成有效证明。

`audit_stage.py` 检查文件基线与碰撞，但不检查骨架、表行、声音或游戏兼容性。它报漂移时停止覆盖，调查新状态。现有安装/扫描脚本通常有单次事务 guard，不能直接重跑旧 `install.py / finalize.py`。

## 退出与备份

离线准备不要求用户退出。真正写入游戏前、恢复/卸载前、加载器或容器变化前重新确认进程已停止；用户说退出但进程重新出现时停止写入并说明。受限沙箱中的空进程列表可能不可靠，应在能看到真实进程的权限下检查。

备份最新 `.sav`、相关 Steam cloud、本次覆盖的 MOD 文件，并保留完整 MOD/容器与加载器配置的可恢复快照。按实际环境发现路径，不固定用户 Steam ID。记录每个文件的相对路径、大小和 SHA-256，复制后验 hash；事务记录新增文件、覆盖前/后 hash 和备份位置。

备份不是修改存档的授权。标题运行可能写 `PBZLocalSetting.sav / PBZSharedSetting.sav`；记录其变化，并单独验证真正进度存档。不要为使检查变绿而回写旧存档。日志/cache 自然更新与配置/程序文件漂移分别判断。

仅按已审查差异写入，写前再查进程，写后验 hash。不会把别的 MOD 或其 loader 跟着删除。若部分写入失败，依据该次事务和当前 hash 复原自有改动；不要覆盖失败期间用户的新修改。

## 标题画面验证

只有有效授权允许时才启动。授权仅限标题时，不模拟 Enter/继续游戏、不加载用户存档；没有运行授权则交付离线候选并明确未运行验证。已经授权的同一操作不再因 Skill 重复询问。

临时 scanner 及辅助文件都先记录原内容/不存在状态，退出后原样恢复。游戏内用无 AI、无碰撞、不被占有的临时 Actor 生成预览；不生成敌人战斗 Blueprint、不传送玩家。不要同时运行多套互相清理的诊断脚本。

等待标题世界实际稳定，不只写死“启动后 18 秒”。已有扫描因 boot-world 切换导致临时 actor 失效；后来用当前 level 名连续稳定约 40 秒再开始。40 秒是案例参数，必须根据当前加载行为判断，并记录 world、phase、失败栈，不能把场景销毁误判为模型失败。

将原主角兼容的 idle/动作序列作为驱动。手动推进时关闭 animation notify，防止触发攻击事件。验证资源真实加载、可见模型的 ABP 及材质、衣料/Groom、附件挂点、运动跟随误差、至少正面/侧面外形、换装清理与原衣装恢复。静态资源加载成功不是动作绑定成功。

头饰等附件用连续多帧测量挂点跟随；头/身体/附件匹配要看动作过程。实际闪现、武器切换、受伤或握武器仍需在用户允许的实战范围验证，不能从 idle 推断全部通过。

## 图片与缩略图验证

SceneCapture 使用仅包含临时 actor 的 show-only 列表，合理取景与灯光。标题全局后处理仍可能影响截图：曾出现整张严重景深模糊，不能用这种图判定贴图缺失。

已验证可临时读取并保存 `r.DepthOfFieldQuality / r.MotionBlurQuality / r.Fog / r.VolumetricFog`，在标题诊断期间设为 0，结束时恢复原值；不写持久配置、不把这些全局开关带到正式 MOD。补拍 `SCS_BaseColor` 可区分纹理与光照问题。截图不清、头饰裁切或占位网格应修正后再作为最终图标。

查看实际导出的图，不只看 API 返回。逐项导入验证自定义 PNG，检查整套衣柜的图标都能解析；新增图案应反映该 variant 本身。

## 结果与恢复

通过后退出游戏，再移除/还原临时 scanner、支持脚本和诊断设置。确认进程已停止、进度存档未被工具更改、无关受管 MOD hash 不变、既有加载器配置仍在。日志里的正常追加不按程序漂移处理。

同步最终候选、legacy/JSON、manifest 与最新源码指针，保留本次回滚记录及有用日志/图片。后续制作从这个当前来源继续，避免把旧 bug 带回。

交付区分三个层级：离线行为/结构检查；标题资源、装配和清理检查；真实游戏操作与用户反馈。存在可复现运行错误或依赖缺失时，修复或按事务回滚受影响候选，不能声称全好。不要因用户暂未实战就把正常候选说成已完成实战测试，也不无限重复同样的失败扫描。
