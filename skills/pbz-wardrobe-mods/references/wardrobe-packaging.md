# 衣柜共存、容器与缩略图

## 唯一身份与单一表

以稳定角色 key 生成衣装、Body/Head 表行、ABP 包路径、provider ID、脚本名、文本键和缩略图映射。阶段/面具/外搭是不同 variant 时分开命名，不复用现有衣装行。按大小写不敏感检查新 ID、provider、包路径和文件路径的碰撞。

维护**当前版本的一份合并 `DT_PBZAppearanceTable`**。多个旧 MOD 各带整张表时，后加载者可能覆盖先前皮肤；这是包覆盖/注册问题，不能凭经验说“衣柜数量满了”。检查所有同路径容器、挂载优先级、Runtime 注册与自动解锁，再判断真实限制。

当前流程可按每个衣装新增 outfit/body/head 三行，但应以当前 schema 为准。保留原有 NameMap 索引、现有表行及本次无关字段；历史表可能已有重复名称，不能随意去重。新增行内部引用及文本键也必须改成新 ID，不能只改行名。

已有脚本对 RawExport 字节进行追加是**特定序列化版本的实现**：例如旧脚本曾用 count 偏移 10、前缀长度 14、行标记查找。它不是通用 UE 表格式。版本变化时重新反序列化/核对 schema；在同版本复用也需断言行数、边界、NameMap 前缀、原有效载荷保持不变，再做运行时读表验证。

## Runtime 所有权

`Variants` 描述资源与衣装；`Appearance` 负责正常衣柜获得流程；`Visual` 负责私有组件；`Registry / Runtime` 管注册、所有权与生命周期。不要直接修改存档来强塞衣装。

沿用 registry 的注册校验：整条声明验证后再写入，不允许未知/重复 outfit 或 provider，注册结束后冻结。新 renderer 激活前调用 activation guard，清理同一 actor 的其他 renderer；旧清理未成功时不继续记录原始可见性。

切回原衣装、衣柜预览快速切换、Pawn 更换以及过场进出都需清理。模型、语音、头发守卫和图标采用明确 ID 映射，但各自覆盖范围可以不同，不让一项的数量断言约束另一项。

## 打包与增量安装

从当前已安装对应的源码分支复制候选，再修改本次所需文件。已有 UAssetGUI JSON/legacy ABP 是减少二进制重建风险的来源；完整替换专属包名与 Skeleton 引用，保留已经验证的图节点逻辑。

参考实现使用 UAssetGUI `fromjson ... --portable` 与 retoc `to-zen` 流程，见证据入口。游戏运行引擎报告、retoc 序列化配置与资源格式版本是不同证据；曾验证过的 `--version UE5_6` 不能因运行日志显示别的版本就盲改，也不能对新版本永远硬编码。

候选 `install` 应包含当前所有受管理文件，diff 只写改变项。不镜像删除整个 `~mods` 或 loader 文件夹。不同加载器可能并存，例如已有 `version.dll` 和另一 MOD 使用的 `dwmapi.dll / ue4ss`；本次角色任务不顺手升级或覆盖它们。

## 缩略图

优先使用匹配角色/阶段的原生 Texture2D，确认表中软引用真实可加载。没有合适原图时，用已装配的私有角色生成 PNG，保留头发、面具、眼镜、头饰及上下边界，选择能在小尺寸识别的角度。

参考实现的 `PortraitIcons.js` 为明确 outfit ID 提供 PNG 映射，`ImportFileAsTexture2D` 加载后设置衣柜 brush。换到无自定义图的衣装时恢复原 brush，避免上一张图片串到下一项。未知衣装不进入该覆盖路径。

自动获得衣装、显示名称、表内软引用与 PNG fallback 各有独立验证；只有文件存在不够。自定义图可在同次标题会话渲染、导入验证，再于退出后复制进最终候选并纳入清单。原生图和自定义图一起检查，避免新角色正常而旧图标丢失。

卸载时先让用户切到保留衣装并保存退出；备份后只移除目标 ID 的注册、表行、图标和私有文件，共享资源按引用保留。不要因卸一个角色回滚整张表到过时版本。
