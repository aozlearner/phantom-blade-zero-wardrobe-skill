# 头发变红、发花与材质保护

先区分问题：

| 症状 | 优先核对 |
| --- | --- |
| 一开始就无头发 | 缺 Groom/ChaosCloth、绑定目标不对、组件不可见、LOD |
| 一开始就白膜/无脸贴图 | 资源与材质槽、CDO 覆盖、依赖未加载、错误 fallback 模型 |
| 换武器或闪现之后变红 | 临时材质/MID 被技能反复替换，或第一次采样已被染色 |
| 细碎闪烁/发花 | 重叠模型或衣料、透明/遮罩槽、LOD、Groom Binding、TAA/抖动与截图条件 |

不要把“发花”一律归因于变红保护，也不要把标题截图中的景深或单帧透明抖动当成真实贴图损坏。

## 现行 HairMaterialGuard 的边界

集中维护一个按衣装 ID 限定的 guard，复用 `HairMaterialGuard.js` 的 `create / step / dispose`。它在当前玩家身上扫描 SkeletalMesh、Groom、ChaosCloth，兼顾头模型内嵌 HairCard 与单独头发。

只处理 owner 为当前 Pawn、属于当前受管衣装、确认是头发的材质槽。排除皮肤、眉毛、睫毛、眼球、原主角头发与其他 actor。保护名单可以包含男性角色；它不应与女性语音名单强行相等。

## 恢复干净基底，而不是缓存红色实例

以组件实例、asset 路径、材质槽数量建立记录。捕获槽位时：

1. 检查当前材质；遇到 MID，有限深度向 `Parent` 回溯并检测循环，寻找稳定的非动态基底。
2. 当前材质已被通用特效替换时，查该组件 asset 的原生 material slot。
3. 应用该衣装明确的材质覆盖。受控玉儿的 P2 白发覆盖优先于 P1 默认材质，含 Groom/HairCard/衣料头发；不能第一次抓到 P1 就永久保存。
4. 只对当前槽引用与已核对基底不同的槽执行组件级 `SetMaterial`；不要改共享材质的颜色参数，不重建整个人物。

一次恢复不够：换武器、闪现会重复写材质。现行守卫按 50 ms 检查，并限制日志量；这是已验证的实现参数，不是其他环境都要使用的频率。首次观察前已变红、连续覆盖、临时隐藏再显示均需处理。

暂时隐藏的已记录头发可保留基底，防止闪现回来后把特效材质重新当原材质。Pawn/衣装改变时清空记录；组件资产或槽数改变时重新采样；销毁对象从缓存移除。暂停、过场时遵循已有守卫策略，不和场景材质效果抢写。

## 测试与诊断

用模拟组件测试：三种组件类型、多槽头模型只恢复头发、连续至少三次 MID 替换、第一次观察已是 MID、隐藏/重现、白发显式覆盖、换装清空、失效对象、NPC owner、眉眼/皮肤排除、SetMaterial 失败隔离。

再检查当前所有受管角色的名单，别把旧测试里的 `17` 或“与女性名单完全相同”照搬到新版本。现有历史 `test_fix.js` 是行为案例来源，旧路径和固定数量断言需要更新。

日志 `CAPTURE / RESTORED / REVIEW` 应说明衣装、组件、asset、槽位与前后路径。不要仅凭出现 `RESTORED` 就保证没有一帧染色；用实际连续换武器、闪现与换装确认。对持续发花另查重叠、绑定、透明与渲染条件。
