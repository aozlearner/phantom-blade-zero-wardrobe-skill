# 按衣柜角色切换战斗语音

本项目的用户规则：女性衣装优先本人战斗声音，缺少的类别用沐小葵；原衣装恢复男声，剧情对白不动。这是该项目约定，不把它强加给用户明确要求其他声音的任务。

## 范围与职责

复用独立 `pbz-female-attack-voice` 模块。`Catalog.js` 管 `OUTFITS: outfitId -> character`、资源分类和音池；`Voice.js` 管攻击播放路由，`HurtVoice.js` 管受伤/发力等补充入口。外观 provider 不再各自安装重复的声音钩子。

先逆向已有女性攻击包，核对原事件路径、Wwise ShortID、播放入口与类别；不要直接覆写全局男主音频文件。Wwise bank/media 的有无不能仅靠扩展名判断，最终要验证事件能加载、能播放。

## 资源分类与回退

从 `/Game/Wwise/Events` 的 registry 取资源，再按已核对的战斗路径与事件名分类。当前目录约定涵盖 combat/battle 及 `VO/Int/Vo_Int_Monster_Battle`，还有少量明确复核的路径例外；新游戏版本不能仅凭模糊关键词放宽到整个 VO 目录。

类别包括 `attack / heavy / charge / hurt / hurtHeavy / break / effort`。跳跃、闪避、发力的入口可能与攻击分开，用户说“还有男声”时先分清动作类别。

保留已验证的选择策略：

- 先取本人相应类别；本人攻击资源缺失时，选择可用的沐小葵阶段音池。
- 缺少重受伤可用本人的普通受伤；缺少破防可按现有策略用重受伤/受伤。
- 缺少反应声时补沐小葵对应反应，不随便拿本人攻击声顶替受伤。沐小葵缺 `effort` 时，现行实现允许其短攻击发力声补充。
- 沐小葵两阶段可在某阶段无独立攻击录音时共享可用阶段。
- 声音对象需有效，能 `LoadData`、取得非零 ShortID，排除无限事件。路径匹配不是播放成功的证据。
- 本人播放失败时按现有模块最多重试一次沐小葵。两者都失败则保留原生音频并记录失败，不让角色无声，也不谎报已成功替换。

排除剧情、对白、过场、死亡、脚步及未确认的事件；不要因为名称中有女性角色名就一概替换。新增死亡等声音必须来自新的明确需求。

## 播放隔离

只拦截当前玩家、当前受管衣装和已登记的源事件。NPC、其他 actor、原衣装和未知事件直通；过场守卫保持原声。不要改共享的原事件对象、Action CDO 或全局 bank。

新声成功取得有效 PlayingID 后，才抑制对应的男声，避免同时播放男女两路。单声道互斥、结束回调释放、时长上限和有限重试沿用既有实现。切换衣装或进入过场，只停止模块自己拥有的 PlayingID，不停止游戏全局音频。

## 验证

离线行为测试至少覆盖：本人优先、缺项回退、播放失败、重复播放、原衣装切回、NPC、剧情/过场直通、对象更换与清理。用真实扫描目录构建模拟音池，另外测试新增衣装，而不只重复检查一个旧角色。

运行检查读取 `EVENT_READY`、`PROFILE_READY`、`REACTION_PROFILE_READY`，确认所选类别及 `ownVoiceAvailable`。这些日志证明资源与选路，不等于已经听过音色；实际攻击、受伤、跳跃和闪避是否自然仍需游戏内确认。

小雪是完整案例：本人 attack/heavy/charge/hurt/break 已可加载，effort 走沐小葵，对应的测试与声音证据应在当前工程中建立；公开仓库不附带原私人日志。
