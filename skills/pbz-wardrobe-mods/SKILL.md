# 影之刃零独立衣柜 MOD

把角色做成可切换、可卸载的衣柜外观，保留主角控制与原衣装。优先扩展已经验证的 PBZModLoader / Puerts 实现；不要从旧压缩包整包覆盖当前安装。

## 先建立当前事实

确认本次角色、阶段、附件、语音要求；用户的新选择优先于旧排除名单。读取当前游戏版本、加载器、安装清单及最新源码指针，核对磁盘状态。先读 [工程证据定位](references/workspace-evidence.md)，按实际工程定位资料，不把日期或旧清单当作当前事实。

用户正在玩时，离线准备候选。操作游戏目录前重新确认进程已退出。沿用本会话有效的退出、安装和扫描授权；若启动权限确实缺失，再解释用途并询问，不因 Skill 再次索要已给出的权限。仅获标题扫描授权时，不进入存档。多个角色一起准备、一起安装、一起验证。

## 制作流程与按需参考

1. **查资源与绑定动作**：读 [模型与动作](references/model-animation.md)。建立每个角色的明确资源配置；确认完整身体、头、头发、衣料、配件与材质。用独立视觉组件跟随原主角动作，不把 NPC 的 AI、碰撞或整套战斗蓝图装到玩家上。
2. **注册衣柜与缩略图**：读 [衣柜与打包](references/wardrobe-packaging.md)。新增唯一的衣装 ID、表行、资源包路径和 provider；维护单一合并表及切换清理。为每项核对可加载的缩略图。
3. **处理声音**：涉及女性衣装或语音修复时，读 [语音规则](references/voice.md)。本项目约定：本人战斗声优先，缺项用沐小葵；切回原衣装恢复男声，剧情对白不改。若用户明确要求其他规则，按新要求修改。
4. **保护头发和材质**：新增有头发的衣装、修复闪现/换武器后变红或发花时，读 [材质保护](references/hair-materials.md)。确认保护名单与该角色的实际组件、材质槽，不对整个人物强行套同一种材质。
5. **备份、安装、验证**：读 [验证与交付](references/validation-install.md)。离线检查通过后备份最新状态，按差异安装；在获准的运行范围内验证，结束后恢复临时扫描器、退出游戏并更新当前源码清单。

## 不可丢失的工程约束

- 原主角的 Pawn、胶囊体、移动、武器插槽、原始动作与控制逻辑继续工作；MOD 只拥有自己的外观组件和明确限定的声音替换。
- 不修改共享 Skeleton、原始材质、全局声音资源来修单一衣装；每个 renderer 跟踪并销毁自己创建的对象，恢复自己保存的原状态。
- 先清理旧 provider，再让新 provider 记录原始可见性。玩家、衣柜预览、过场外观有各自生命周期，不能靠“换了模型文件”推断都能工作。
- 白发、面具、眼镜、外搭等都是明确资源需求；不以文件名近似、资源能加载或一张正面图代替装配验证。
- 标题检查证明资源与临时模型可工作，不证明实战、闪现、换武器一定正确。分别报告离线检查、标题检查、用户实战确认的证据。

## 差异审计辅助

`scripts/audit_stage.py` 对照当前基线、游戏目录和候选目录，报告文件漂移、未知文件碰撞、缺失文件及写入范围。只适用于新增/修复的完整候选目录，不执行备份或安装，不检查动画、表行或运行兼容性。

```powershell
python <skill-dir>/scripts/audit_stage.py --baseline <current-manifest.json> --game <game-root> --stage <candidate-install> --report <workspace>/stage-audit.json
```

退出码 0 仅表示文件基线检查通过；1 表示存在需处理的冲突；2 表示输入无效。出现漂移先调查并重建基线，不自动覆盖用户后来做的修改。卸载需单独列明拥有的文件、共享表行和配置迁移，不用此辅助代替卸载计划。

## 交付

说明新增/修复的衣柜名称、语音规则、备份位置、实际验证范围，以及游戏是否已退出。保留安装清单、差异与回滚记录，更新最新源码入口。不要把固定的衣柜数量、历史测试输出里的旧数字、某次引擎版本或安装路径写成永久上限。
